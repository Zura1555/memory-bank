The Worker is the sole online API and serves the browser assets built with the Cloudflare Vite plugin into `.cloudflare/output/v0/`. The pinned `cf` CLI builds and deploys `cloudflare.config.ts` without Wrangler. Hono routes implement the shared contract in `../shared/protocol.ts`; model outputs are not returned until exact reference checks and a separate support review complete. Production database access uses Hyperdrive; local development uses a real PostgreSQL connection only when `APP_ENV=development`. No credentials or fixture response path is compiled into the Worker.

OpenRouter requests pin the OpenAI route with strict parameter support and no fallback. Omit `temperature`: the configured `openai/gpt-6-luna` OpenAI endpoint does not advertise it as supported. Keep admission disabled after a provider rejection until the request is corrected and a new paid attempt is explicitly approved; metadata compatibility is not proof of successful inference.

Requests explicitly set `stream: false`; the response reader expects one JSON envelope, not SSE events. A completed provider generation does not prove that the app accepted its response. Unexpected transport or envelope failures remain uncertain and require reconciliation against provider records before another admission.

Each model request has a 120-second deadline covering headers and the complete response body; its Workflow step has a 135-second deadline. The UI's 90-second assessment and 30-second brief values are processing targets, not cancellation deadlines. A timeout after dispatch remains uncertain, has no automatic retry, and retains `X-Generation-Id` in operator status when supplied by the provider.

Draft prompts require the same artifact coverage and claim membership enforced by structural checks: every available assessment artifact and every selected brief item is classified, and blockers/verification claims belong to the item's claim set with exact artifact evidence. Invalid drafts are rejected, not patched into plausible output.

Assessment outputs contain an inline recommendation and inline supporting, blocker, and verification claims per artifact. The server assigns unique IDs and constructs role membership from containment; it never copies global case claims into artifact roles, repairs prose, adds citations, or drops invalid roles. Every local claim must directly cite its owning case/artifact; dependencies on global claims preserve full-case context without replacing that evidence. The unchanged provenance gate rejects sibling-artifact citations. The schema forbids unchanged reuse with blockers/checks and requires a concrete recommendation claim for verify items. API result shapes and brief inputs remain unchanged.

Assessment generation makes useful-lead membership an explicit `usefulForLead` choice on each artifact. The strict schema requires `false` for verify work; reuse/adapt may be nominated or left out. Each case has one generated lead/contrast/context tier. The parser derives the existing API tier lists and `usefulArtifactIds` by containment; it does not promote every reuse/adapt artifact or reclassify verify work. Independent artifact-role review and the `LEAD_ARTIFACT_NOT_USABLE` defense remain in force.

Review wire schemas require `claimVerdicts`, a strict object keyed by every current draft claim ID, then normalize to the existing canonical `claimReviews` array. Omitted or foreign keys fail; the model still decides every verdict independently. A brief's checked assessment is background, not another review inventory. Assessment review independently checks every claim, outcome/disposition classification, and every available artifact's implementation role. The server derives the aggregate conclusion from complete reviewed coverage and surviving nominated work; true historical facts alone cannot establish an implementation precedent.

The assessment workbench adds at most 24 decisive comparison rows across product/version, environment, scale, identity/access, and recovery/operations. The draft supplies an exact requirement quotation (or null/unknown) and inline evidence, relation, and implication roles. The parser assigns distinct source-fact/interpretation/recommendation claims and dependency links by containment. Requirement claims explicitly state that the current request contains the quoted text; they do not assert historical compatibility. The existing independent reviewer checks every role and the row's semantics; rejected dependencies withhold the entire row. Accepted conflicts/unknowns may explain an unestablished lead without promoting its work. No score or paid stage is added.

Assessment and brief draft wire references use short passage labels assigned in pinned-manifest order, including unavailable entries so labels never rebind. The brief context uses that same index and its schema permits only actual available passages from exact selected artifact versions. Assessment global claims, comparison cells and inline reasons are bound to their owning case; artifact-local claims are bound to their own artifact. Normalization restores canonical exact case/artifact/version/passage IDs before existing ownership/reference checks. Unknown/unavailable labels fail closed. Review and brief input documents factor repeated valid reference tuples into a document-local `sourceReferenceIndex`; invalid tuples remain verbatim rather than being repaired by passage ID. All claims, dependencies, classifications, full original excerpts, eight-case coverage and selected-case context remain present. Stored normalized outputs, API results, selections and gates retain canonical references. Global claims nominate their owning case and observed-outcome evidence; the parser constructs case/outcome ID lists instead of independently generating them.

The same provider input documents encode claims as `claimFields` plus `claimRows` to remove repeated JSON keys. Each row preserves all six canonical claim fields in header order, including complete text, references, exact request quotations and dependency IDs. Review instructions require decoding every row; target inventories and canonical stored output remain unchanged. This is lossless representation, not summary or evidence truncation.

Each non-unknown outcome with nominated evidence is normalized into a server-owned `outcome-N` interpretation claim stating the exact classification and depending on all nominated outcome facts. The existing independent support review must judge that label separately from factual truth; no paid stage or new verdict category is added. The gate requires the supported classification to match the displayed label and all its evidence to survive reference/dependency checks. Rejected, uncertain, missing, or evidence-free classifications become Unknown, never a replacement label. Revalidation also makes older stored outcomes without this classification claim Unknown while preserving supported case facts.

Every available artifact, including non-lead/contrast work, also receives a server-owned `classification-disposition-N-M` interpretation stating its exact attached Reuse/Adapt/Verify label and depending on its recommendation and all local roles. The existing support-review inventory checks this classification independently from recommendation truth: Reuse supports unchanged use without a decisive blocker/check; Adapt supplies usable starting material and concrete changes/checks; Verify states a concrete decision-critical check. Rejected, uncertain, missing, mismatched, or dependency-withheld classifications withhold the work, never relabel it. Such work cannot supply useful-lead membership, selected passages, or next actions; supported Adapt work survives independently. Revalidation withholds legacy dispositions without these checks rather than grandfathering them into the new guarantee. Drain active workflows before cutover; no paid stage or API shape is added.

At most three next actions are derived from accepted request-specific artifact verification/blocker recommendations, preferring current lead checks. Each recommendation must state the check and its effect on reuse; reviewed lessons still require original evidence and request applicability. Unsupported work or dependencies cannot supply an action. Empty actions and no-precedent conclusions remain valid.

A bounded no-useful-precedent conclusion requires complete usable evidence, no reference/requirement conflict, a settled negative role for every available artifact, and at least one accepted mismatch/unknown comparison or independently checked exclusion with its dependency closure. Draft/review presence disagreements block negative proof even when no comparison row covers the disputed dimension; different exact quotations of the same present dimension need not be identical. Negative roles alone are not an explanation. Relevant unresolved roles block that conclusion; an unrelated historical outcome may remain Unknown without overriding the complete, independently checked artifact-role decision. Revalidation never upgrades a stored Cannot-be-established result.

For an existing database, apply any missing migrations in order, including `migrations/0002_assessment_workbench.sql` and `migrations/0003_model_failure_diagnostics.sql`, before starting this Worker revision. Migration 0002 adds empty comparison/action inventories to older checked results without reinterpreting claims; 0003 supplies columns required by diagnostic persistence and operator status. Fresh local databases apply all migrations on initialization. Keep admission disabled, drain active workflows and verify a private backup before cutover: old in-flight outputs do not satisfy the new strict review contract. Do not infer that an existing deployment already has migration 0003.

Ready job responses revalidate the pinned manifest and original hashes before serving claims. Lost or corrupted evidence withholds its claims, transitive dependants, and affected work items. Brief admission and execution use the revalidated assessment. Restoring exact evidence can restore the original checked result without another model call.

Paid Workflow steps checkpoint either an attempt ID or a serializable failure code/uncertainty outcome. Typed exceptions are classified inside the step, before the platform can serialize them into generic errors. Unresolved dispatches still require reconciliation and cannot be replayed into another paid call.

Reviewed decision/lesson records are loaded only from the schema-v2 curator manifest. Knowledge APIs and the independent card UI do not read or promote job content. Both draft and support-review contexts include available cards, exact SourceRefs, assertion basis, and derived supersession markers; missing evidence never makes superseded advice current again. Existing recommendation/reference/support-review gates apply to any new-client lesson application. See `../../docs/qualification-2026-10-15.md` for the observed baseline and unresolved assessment-quality failures; readiness is not a blanket semantic-quality guarantee.

Provider cases and each case's available artifact inventory are strict required-key objects. The parser derives case/artifact identities from supplied keys and restores existing API arrays; it never fills a missing entry or repairs a claim. Case-local lead/contrast reasons are inline claims with case-bound citations; normalization assigns their IDs and preserves them in independent review. Brief input requires one keyed case/artifact/version decision per exact selection; Reuse/Adapt/Verify sections derive from that single disposition rather than independent lists. Shared JSON Schema definitions avoid repeating inventory schemas; oversized input still fails the existing request-size limit. Drafting and review independently extract constraints using shared dimension meanings. A sentence that only asks to inspect or advise is not a constraint. An explicit operating deadline, required completion proof, or rejected substitute is operational acceptance even when unconfirmed. Product/API match or mismatch needs established lineage and an explicit version relationship; otherwise compatibility remains unknown without erasing supported conditional Adapt. Inventory conflicts and unsupported classifications still fail closed.

Selection identity compares explicitly ordered case/artifact/version fields and sorted passage IDs, not incidental JavaScript versus PostgreSQL JSONB property order. Reopening the same queued/running/ready brief returns its existing state without another reservation or provider dispatch.

Missing or chronologically inconsistent phase timestamps produce null observed timings, never a fabricated zero-duration result. The UI distinguishes unavailable timing from the 90 s / 30 s targets. Wall-clock timestamps are not a monotonic performance measurement. When the local clock is discontinuous, qualification uses external `process.hrtime` and direct durable-state reads to bound processing transitions independently of HTTP proxy/poll delays; database wall durations and wider HTTP-observation bounds remain separately recorded, not silently replaced.
