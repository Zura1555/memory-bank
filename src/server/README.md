The Worker is the sole online API and serves the browser assets built with the Cloudflare Vite plugin into `.cloudflare/output/v0/`. The pinned `cf` CLI builds and deploys `cloudflare.config.ts` without Wrangler. Hono routes implement the shared contract in `../shared/protocol.ts`; model outputs are not returned until exact reference checks and a separate support review complete. Production database access uses Hyperdrive; local development uses a real PostgreSQL connection only when `APP_ENV=development`. No credentials or fixture response path is compiled into the Worker.

`MODEL_PROVIDER` selects `openrouter` (default), `openai` (Chat Completions-compatible), `anthropic` (Messages-compatible), or `opencode-go`. `MODEL_NAME` is required outside OpenRouter; Go also requires `MODEL_API=chat-completions|messages|responses`, with no model-name guessing. `MODEL_BASE_URL` overrides the versioned API base, including any gateway prefix and `/v1`. Credentials are selected only from `OPENROUTER_API_KEY`, `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `OPENCODE_API_KEY`, respectively; there is no credential or provider fallback. Development settings/credentials are declared as local secret bindings so `.dev.vars` reaches the actual Worker. See the root README for configuration examples and Go defaults.

OpenRouter retains its existing `openai/gpt-6-luna` default, pinned OpenAI route, strict parameter support, and no fallback. OpenAI-compatible requests use strict `response_format` JSON Schema without OpenRouter-only routing/reasoning/plugins. Anthropic-compatible requests use a forced single `submit_result` tool with the stage's `input_schema`; only a completed `tool_use` result is accepted. Every provider's output is validated and normalized against the original Zod schema before existing reference/support gates. No tools execute. Endpoints must support the selected protocol, the stage schemas, and the 16,384-token output bound. Compatibility is not paid model/workflow qualification.

Go reuses those Chat Completions/Messages adapters and adds a Responses path using strict `text.format`, `max_output_tokens: 16384`, and `store: false`. Responses must contain one completed assistant JSON message (optional reasoning items are ignored); refusal, incomplete status/details, error, extra tool calls and ambiguous messages fail closed. Safe `resp_` IDs survive failure diagnostics. All three Go routes send `User-Agent: memory-bank/0.1.0` and `x-opencode-session: <job UUID>` from `runPaidStage`, never a capability or fresh per-call ID. The persisted job ID spans both phases and process restarts without a new database field. Missing/invalid sessions fail before dispatch.

Real Go inference is not qualified: no credential was available to verify strict stage schemas or forced-tool behavior upstream. The loopback protocol checks do not establish model quality, context fit, pricing or permission to send this non-coding workload. Confirm Go usage-policy suitability and model-specific retention, then qualify all four stages before enabling admission. Native Gemini endpoints are outside the implemented protocols.

Omit `temperature`. Keep admission disabled after a provider rejection until the request is corrected and a new paid attempt is explicitly approved; metadata compatibility is not proof of successful inference. Changing endpoint/model requires draining active workflows and reconciling prior charges before reusing a campaign balance. HTTPS is required except loopback HTTP for local servers; credentials in URLs, query strings/fragments, and redirects are rejected. `/api/model-info` discloses only provider, model and endpoint origin for intake processing notices, never API keys or private gateway paths.

Provider fetches use `redirect: "manual"`: Workers rejects `"error"` before dispatch. Redirect responses reach the existing non-2xx rejection path without following their location or forwarding credentials/request content.

Requests explicitly set `stream: false`; the response reader expects one JSON envelope, not SSE events. A completed provider generation does not prove that the app accepted its response. Unexpected transport or envelope failures remain uncertain and require reconciliation against provider records before another admission.

Output failures distinguish a missing choice/text, an output token limit, refusal, content filtering, and other non-stop completion. Once a response envelope is valid, the failed attempt retains its reported token counts/cost, generation ID, model and provider in the existing operator-only usage fields, including invalid JSON or schema output. Unreported token counts and cost remain null, never zero. Partial output, refusal text and arbitrary finish-reason strings are not retained. These diagnostics do not accept output, settle charges, release holds or permit replay; the existing uncertain/reconciliation boundary remains unchanged.

Each model request has a 120-second deadline covering headers and the complete response body; its Workflow step has a 135-second deadline. The UI's 90-second assessment and 30-second brief values are processing targets, not cancellation deadlines. A timeout after dispatch remains uncertain, has no automatic retry, and retains `X-Generation-Id` in operator status when supplied by the provider.

Draft prompts require the same artifact coverage and claim membership enforced by structural checks: every available assessment artifact and every selected brief item is classified, and blockers/verification claims belong to the item's claim set with exact artifact evidence. Invalid drafts are rejected, not patched into plausible output.

Assessment outputs contain an inline recommendation and inline supporting, blocker, and verification claims per artifact. The server assigns unique IDs and constructs role membership from containment; it never copies global case claims into artifact roles, repairs prose, adds citations, or drops invalid roles. Every local claim must directly cite its owning case/artifact; dependencies on global claims preserve full-case context without replacing that evidence. The unchanged provenance gate rejects sibling-artifact citations. The schema forbids unchanged reuse with blockers/checks and requires a concrete recommendation claim for verify items. API result shapes and brief inputs remain unchanged.

Assessment generation makes useful-lead membership an explicit `usefulForLead` choice on each artifact. The strict schema requires `false` for verify work; reuse/adapt may be nominated or left out. Each case has one generated lead/contrast/context tier. The parser derives the existing API tier lists and `usefulArtifactIds` by containment; it does not promote every reuse/adapt artifact or reclassify verify work. Independent artifact-role review and the `LEAD_ARTIFACT_NOT_USABLE` defense remain in force.

Review wire schemas require `claimVerdicts`, a strict object keyed by every current draft claim ID, then normalize to the existing canonical `claimReviews` array. Omitted or foreign keys fail; the model still decides every verdict independently. A brief's checked assessment is background, not another review inventory. Assessment review independently checks every claim, outcome/disposition classification, and every available artifact's implementation role. The server derives the aggregate conclusion from complete reviewed coverage and surviving nominated work; true historical facts alone cannot establish an implementation precedent.

Historical assertions require support from the claim's own cited passages or explicit transitive claim dependencies. Full-case context can veto a claim through counterevidence or a missing qualification, but cannot fill an uncited assertion's provenance. Comparison cells stay within their owning case; other-case history belongs in a separately sourced claim or that case's own row. A historical total must preserve a material unreconciled count discrepancy with both source statements cited, not silently choose or reconcile counts.

Drafting and independent review require material pre-use checks for offered external-service/API procedures, explicitly including current-client authentication/authorization when access is unestablished. Artifact-role decisions constrain every visible offering, including global claims, case reasons and comparison implications: context-only material cannot become a conditional starting point through a different prose label or a withheld disposition. Negative context and requests for missing evidence remain permissible. These are model-semantic instructions, not a deterministic prose classifier; new output must still be independently qualified.

The assessment workbench adds at most 24 decisive comparison rows across product/version, environment, scale, identity/access, and recovery/operations. The draft supplies an exact requirement quotation (or null/unknown) and inline evidence, relation, and implication roles. The parser assigns distinct source-fact/interpretation/recommendation claims and dependency links by containment. Requirement claims explicitly state that the current request contains the quoted text; they do not assert historical compatibility. The existing independent reviewer checks every role and the row's semantics; rejected dependencies withhold the entire row. Accepted conflicts/unknowns may explain an unestablished lead without promoting its work. No score or paid stage is added.

Global assessment `source_fact` claims describe historical records and cannot carry current-request quotations in either the provider schema or runtime parser. A current-request constraint belongs in a separate `interpretation` with an exact quotation and explicit request attribution; its historical references supply comparison context, not proof of the client's capabilities. Independent review judges that request statement against the request, while historical facts, compatibility conclusions and every dependency still require their own support. This prevents a misclassified request constraint from poisoning otherwise supported conditional Adapt material; rejected or uncertain requirements still withhold their dependents.

All assessment quotation fields use the same exact current-request sentence/chunk choices, including lead reasons and artifact-local claims. Brief quoted interpretations/recommendations use one such quotation per atomic claim; the runtime schema requires it verbatim in visible prose through a literal substring pattern (request punctuation is escaped, never executable regex), and the checked-brief gate repeats that check. Generation is instructed per selected item: every decisive quotation affecting an item gets its own dedicated atomic recommendation in that item's claim set, with the quotation in both prose and its one-element `requestQuotes` and references from that exact artifact/version, so a quotation shared by two items is repeated per item and a disposition claim carries at most one quotation. The runtime schema also rejects any claim whose prose contains a verbatim request sentence/chunk that is not its sole `requestQuotes` entry, so a draft that would certainly be withheld at coverage is refused at parse time instead of consuming the independent review; no output is repaired or inserted. The brief provider grammar omits those unanchored sentence patterns after a captured brief dispatch returned an empty `length` response with no usage in about 2.7 seconds, while the far larger anchored-pattern assessment grammar completed; runtime parsing and coverage gates still fail closed on hidden quotation metadata. Unquoted historical facts remain separate. Independent brief review selects relevant quotations from the same request-bound choices, not from draft answers. This aligns quotation identity before existing coverage/support gates without inserting text, choosing relevance, approving claims or changing stored canonical API shapes. Brief coverage binds a quotation to an item only when the item's own checked work both declares and states it, or the draft itself associates it with that item; a brief reviewer's per-item inventory cannot by itself erase an item, while assessment-bound and draft-associated quotations remain fully enforced. The brief wire decision's disposition claim is composed into its item server-side (existence and recommendation kind still validated, never repaired), so a mere listing omission cannot fail the whole brief. A quoted brief claim's declared request sentence is likewise composed verbatim into its text server-side (the claim must still declare exactly that sentence; prose containing a different quotation is still rejected), so constraint coverage never depends on the model retyping a long sentence inside prose. Item-level coverage rejection applies to assessment-bound quotations; a quotation the draft alone associated with an item is carried when its claims pass review and simply not covered when they are withheld singly, so one uncertain check cannot erase an otherwise covered item.

Procedural recommendations preserve material failed attempts and corrective prerequisites in the assessment's historical rationale. They retain documented roles/authority, escalation, acceptance and stop conditions as applicable; new-client responsibilities and target mechanics must be explicitly agreed or verified rather than inherited from past names, signatures, support windows or matching counts. Briefs keep selected-source prerequisites as adaptations/checks without attributing another artifact's corrective history to the selected source. The existing independent reviews judge these conditions; missing support still withholds work rather than forcing Adapt.

Assessment and brief draft wire references use short passage labels assigned in pinned-manifest order, including unavailable entries so labels never rebind. The brief context uses that same index and its schema permits only actual available passages from exact selected artifact versions. Assessment global claims, comparison cells and inline reasons are bound to their owning case; artifact-local claims are bound to their own artifact. Normalization restores canonical exact case/artifact/version/passage IDs before existing ownership/reference checks. Unknown/unavailable labels fail closed. Review and brief input documents factor repeated valid reference tuples into a document-local `sourceReferenceIndex`; invalid tuples remain verbatim rather than being repaired by passage ID. All claims, dependencies, classifications, full original excerpts, eight-case coverage and selected-case context remain present. Stored normalized outputs, API results, selections and gates retain canonical references. Global claims nominate their owning case and observed-outcome evidence; the parser constructs case/outcome ID lists instead of independently generating them.

The same provider input documents encode claims as `claimFields` plus `claimRows` to remove repeated JSON keys. Each row preserves all six canonical claim fields in header order, including complete text, references, exact request quotations and dependency IDs. Review instructions require decoding every row; target inventories and canonical stored output remain unchanged. This is lossless representation, not summary or evidence truncation.

Each non-unknown outcome with nominated evidence is normalized into a server-owned `outcome-N` interpretation claim stating the exact classification and depending on all nominated outcome facts. The existing independent support review must judge that label separately from factual truth; no paid stage or new verdict category is added. The gate requires the supported classification to match the displayed label and all its evidence to survive reference/dependency checks. Rejected, uncertain, missing, or evidence-free classifications become Unknown, never a replacement label. Revalidation also makes older stored outcomes without this classification claim Unknown while preserving supported case facts.

Every available artifact, including non-lead/contrast work, also receives a server-owned `classification-disposition-N-M` interpretation stating its exact attached Reuse/Adapt/Verify label and depending on its disposition recommendation alone. The existing support-review inventory checks this classification independently from recommendation truth: Reuse supports unchanged use without a decisive blocker/check; Adapt supplies usable starting material and concrete changes/checks; Verify states a concrete decision-critical check. Rejected, uncertain, missing, mismatched, or dependency-withheld classifications withhold the work, never relabel it. Work and brief items otherwise survive claim-by-claim: dependency closure withholds any claim whose declared dependencies were withheld, each surviving claim was independently judged supported, and a withheld sibling claim removes only itself (it is counted in `withheldClaimCount` and cannot supply selected passages or next actions). A withheld disposition or classification claim still removes the whole work or item. Revalidation withholds legacy dispositions without these checks rather than grandfathering them into the new guarantee. Drain active workflows before cutover; no paid stage or API shape is added.

At most three next actions are derived from accepted request-specific artifact verification/blocker recommendations, preferring current lead checks. Each recommendation must state the check and its effect on reuse; reviewed lessons still require original evidence and request applicability. Unsupported work or dependencies cannot supply an action. Empty actions and no-precedent conclusions remain valid.

A bounded no-useful-precedent conclusion requires complete usable evidence, no reference/requirement conflict, a settled negative role for every available artifact, and at least one accepted mismatch/unknown comparison or independently checked exclusion with its dependency closure. Draft/review presence disagreements block negative proof even when no comparison row covers the disputed dimension; different exact quotations of the same present dimension need not be identical. Negative roles alone are not an explanation. Relevant unresolved roles block that conclusion; an unrelated historical outcome may remain Unknown without overriding the complete, independently checked artifact-role decision. Revalidation never upgrades a stored Cannot-be-established result.
