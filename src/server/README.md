The Worker is the sole online API and serves Vite's `dist/` assets. Hono routes implement the shared contract in `../shared/protocol.ts`; model outputs are not returned until exact reference checks and a separate support review complete. Production database access uses Hyperdrive; local development uses a real PostgreSQL connection only when `APP_ENV=development`. No credentials or fixture response path is compiled into the Worker.

OpenRouter requests pin the OpenAI route with strict parameter support and no fallback. Omit `temperature`: the configured `openai/gpt-6-luna` OpenAI endpoint does not advertise it as supported. Keep admission disabled after a provider rejection until the request is corrected and a new paid attempt is explicitly approved; metadata compatibility is not proof of successful inference.

Requests explicitly set `stream: false`; the response reader expects one JSON envelope, not SSE events. A completed provider generation does not prove that the app accepted its response. Unexpected transport or envelope failures remain uncertain and require reconciliation against provider records before another admission.

Each model request has a 120-second deadline covering headers and the complete response body; its Workflow step has a 135-second deadline. The UI's 90-second assessment and 30-second brief values are processing targets, not cancellation deadlines. A timeout after dispatch remains uncertain, has no automatic retry, and retains `X-Generation-Id` in operator status when supplied by the provider.

Draft prompts require the same artifact coverage and claim membership enforced by structural checks: every available assessment artifact and every selected brief item is classified, and blockers/verification claims belong to the item's claim set with exact artifact evidence. Invalid drafts are rejected, not patched into plausible output.

Assessment outputs contain an inline recommendation and inline supporting, blocker, and verification claims per artifact. The server assigns unique IDs and constructs role membership from containment; it never copies global case claims into artifact roles, repairs prose, adds citations, or drops invalid roles. Every local claim must directly cite its owning case/artifact; dependencies on global claims preserve full-case context without replacing that evidence. The unchanged provenance gate rejects sibling-artifact citations. The schema forbids unchanged reuse with blockers/checks and requires a concrete recommendation claim for verify items. API result shapes and brief inputs remain unchanged.

Assessment generation makes useful-lead membership an explicit `usefulForLead` choice on each artifact. The strict schema requires `false` for verify work; reuse/adapt may be nominated or left out. Lead metadata no longer generates a separate artifact-ID list: the parser constructs the unchanged API `usefulArtifactIds` from those choices within the nominated case. It does not promote every reuse/adapt artifact or reclassify verify work. Contrasts retain their existing artifact lists. The independent lead compatibility review and `LEAD_ARTIFACT_NOT_USABLE` defense remain in force.

Review schemas enumerate only the current draft's claim IDs. A brief's checked assessment is background, not an additional review inventory. Assessment review separately checks proposed lead artifacts against the requested capabilities and records a whole-corpus conclusion; true historical facts alone cannot establish an implementation precedent.

The assessment workbench adds at most 24 decisive comparison rows across product/version, environment, scale, identity/access, and recovery/operations. The draft supplies an exact requirement quotation (or null/unknown) and inline evidence, relation, and implication roles. The parser assigns distinct source-fact/interpretation/recommendation claims and dependency links by containment. Requirement claims explicitly state that the current request contains the quoted text; they do not assert historical compatibility. The existing independent reviewer checks every role and the row's semantics; rejected dependencies withhold the entire row. Accepted conflicts/unknowns may explain an unestablished lead without promoting its work. No score or paid stage is added.

Assessment drafts use short passage labels assigned in pinned-manifest order, including unavailable entries so labels never rebind. Only the draft context uses labels; normalization restores canonical exact case/artifact/version/passage IDs before ownership/reference checks and independent review. Unknown/unavailable labels fail closed. All eight cases, exact excerpts, reviewed records, outcomes, corrections, model route, token ceiling, and deadlines remain intact. Global claims explicitly nominate their owning case and whether they establish its observed outcome; the parser constructs case/outcome ID lists rather than independently generating them. An empty compatibility-review inventory forbids `precedent_found` in the dynamic provider schema; the defensive gate remains unchanged.

At most three next actions are derived from accepted request-specific artifact verification/blocker recommendations, preferring current lead checks. Each recommendation must state the check and its effect on reuse; reviewed lessons still require original evidence and request applicability. Unsupported work or dependencies cannot supply an action. Empty actions and no-precedent conclusions remain valid.

For an existing database, apply `migrations/0002_assessment_workbench.sql` before starting the new Worker. It adds empty comparison/action inventories to older checked results without reinterpreting their claims. Fresh local databases apply both migrations on initialization. Stop/drain active workflows before cutover: old in-flight draft outputs do not satisfy the new strict comparison contract.

Ready job responses revalidate the pinned manifest and original hashes before serving claims. Lost or corrupted evidence withholds its claims, transitive dependants, and affected work items. Brief admission and execution use the revalidated assessment. Restoring exact evidence can restore the original checked result without another model call.

Paid Workflow steps checkpoint either an attempt ID or a serializable failure code/uncertainty outcome. Typed exceptions are classified inside the step, before the platform can serialize them into generic errors. Unresolved dispatches still require reconciliation and cannot be replayed into another paid call.

Reviewed decision/lesson records are loaded only from the schema-v2 curator manifest. Knowledge APIs and the independent card UI do not read or promote job content. Both draft and support-review contexts include available cards, exact SourceRefs, assertion basis, and derived supersession markers; missing evidence never makes superseded advice current again. Existing recommendation/reference/support-review gates apply to any new-client lesson application. See `../../docs/qualification-2026-10-15.md` for the observed baseline and unresolved assessment-quality failures; readiness is not a blanket semantic-quality guarantee.
